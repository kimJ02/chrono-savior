# 픽셀(도트) 기준 — 현재 기술 기준 (2026-11-06)

> 이 문서는 **지금 프로젝트가 실제로 어떻게 그리고 있는지**와 **확인된 규칙**을 적는다. 외주 작가에게 줄 **최종 규격은 아직 아니다** —
> 외주 VFX·배경·캐릭터 그림의 PPU·크기가 정해지면(아직 미정) 이 문서를 그 기준으로 고친다(`HANDOFF.md` '중간 점검과 남은 계획' 5번 — VFX 납품 뒤 시각 재작업).
> 기준 캡처: `docs/baseline-2026-11-06/`(stage 3장 = 월드 960×540 원본 크기, ui = 화면별 640×360 + 전투HUD·로비 1080).

## 0. 확정(2026-11-09): **화면의 도트 크기는 하나 — 배율 2**

사용자 "도트 크기를 맞춰야"(이런 류 도트 게임처럼), Codex와 배율 1·2를 비교해 **2**로 정함(1이면 캐릭터·폭발이 너무 작고 땅·배경·발판을 다시 그려야 한다).
코드 기준은 `Core.DotScale`(그림 1px = 월드 격자 2칸, 격자 PPU 128·기준 960×540). 아래 2절의 옛 표는 이 결정 전 기록이다.

- **월드 그림 전부 배율 2**: 땅·발판 타일 PPU 64(그대로 깐다), 배경·포탈 PPU 128 × 2, 캐릭터 32×48 → 0.5×0.75유닛(판정 지름 0.5는 그대로 — 그림 기준점을 아래 1/3로 두어 발이 판정 원 바닥에), 고블린·박쥐 32px → 0.5유닛.
- **엘리트**: 그림은 일반 몹과 같은 도트(예전 ×1.35 → 2.7), 판정만 ×1.35. 엘리트 표시는 원본 `drawEnemy`(:4780)의 보라 오라·금색 왕관(`Enemies/EnemyElite` — 예전 Unity엔 없었다).
- **이펙트**: 판정 크기에 맞춰 늘리지 않는다 — 크기 차이는 **작은/큰 그림 고르기**(중력 구체 중첩 1~2 작은·3~5 큰, 대붕괴 중첩 1~2 가시 고리·3~5·임계 큰 번개 충격, 레이저 1~4층 small·5층 large), **범위는 판정 고리**(`Combat/RangeRing` — 실행 중에 그린 1px 도트 원, 0.3초). 길이만큼 이어 붙이는 것(레이저 몸통·중계선)은 도트 그대로.
- **예외**: 그림 없는 임시 도형 몹(오우거·멧돼지·해골·슬라임·보스·성소 — 128px 매끈한 도형)은 그림이 들어올 때 맞춘다. UI는 따로(3절).
- **배경 배율 3 → 2**: 640×360이 10×5.6유닛으로 화면을 덮는다. 위 19px 바위 테두리가 드러나지 않게 `StageArtSet.backgroundTopPx`로 숨겨서, 땅에 섰을 때 그림 속 풀밭이 우리 지면보다 조금(그림 33px) 위에 온다.
- 테스트 `World/DotScaleTests`(캐릭터·그림 있는 몹·배경·포탈·타일), 이펙트 배율은 `MageVfxTests`·`MechanicAssassinVfxTests`.

## 1. 확인된 사실 (월드)

- 카메라는 **상주 씬(`00_Persistent`)에 하나** — URP `PixelPerfectCamera`, **assets PPU 128**, 기준 해상도 **960×540**, Grid Snapping **Upscale Render Texture**, Crop Frame **Stretch Fill**.
  로비(`10_Lobby`)·전투(`20_Combat`) 모두 이 카메라로 그린다 — 씬마다 도트 규격이 다르지 않다.
- 월드는 먼저 960×540 격자(= **1유닛에 128칸**)로 그린 뒤 화면 크기로 키운다(1080p면 2배).
- **그림 한 픽셀이 차지하는 격자 칸 수(= 도트 배율)** = `128 × 화면에서 차지하는 크기(유닛) ÷ 그림의 픽셀 수` (= `128 × Transform 배율 ÷ 그림 PPU`).
  - 1이면 그림 한 픽셀 = 격자 한 칸(가장 또렷).
  - 2·3 같은 정수면 도트가 고르게 커진다.
  - 1.33처럼 **정수가 아니면 도트 폭이 고르지 않다**(어떤 픽셀은 1칸, 어떤 픽셀은 2칸) — 움직일 때 지글거린다.
  - 1보다 작으면 그림이 줄어들어 픽셀이 빠진다(아래 원·삼각형 같은 매끈한 도형은 티가 덜 난다).
- 필터: 도트 그림은 Point(필터 없음, `filterMode: 0`).

|---|---|---|---|
| 발판 타일 | 16×16 · 128 | 그대로 | **1** |
| 땅(윗면·흙) | 32×32 · 64 | 그대로 | **2** |
| 배경(1스테이지 숲) | 640×360 · 128 | 그림 묶음 `StageArtSet.backgroundScale` = 3 | **3** |
| 보스 포탈 | 32×64 · 128 | 그림 묶음 `StageArtSet.portalScale` = 1.5(사용자 결정) | **1.5** |
| 플레이어(임시 캐릭터) | 32×48 · 128 | 그림 높이 `CharacterArtSet.heights` = 0.5유닛(판정 높이와 같게 둠) | **1.33** |
| 고블린(멧돼지 그림) | 32×32 · 100 | 그림 높이 `EnemyData.visualHeight` = 0.5(판정 지름과 같게 둠) | **2.0** (엘리트 ×1.35 → 2.7) |
| 박쥐 | 32×32 · 100 | `visualHeight` = 0.37(판정 지름과 같게 둠) | **1.48** (엘리트 2.0) |

| 보스·성소 | 임시 도형(삼각형·사각형) 128×128 · 128 | 그림 크기 `MonsterCatalog.bossSize`·`shrineSize` — 가로·세로 **따로**(보스 1.3×1.5, 성소 0.64×0.96유닛) | 가로·세로 다름 |
| 살수 베기 효과 | 96×96 · 128(Slash Vol 2, 2026-11-07) | `BladeSlashVfx.Scale` = 2 | **2** |
| 마법사 이펙트(2026-11-07, 라이선스 팩 — git 밖) | 24~96px · 128 | 정수 배율: 차지 오라 1 · 화염탄 2~5 · 중력탄 1~2(판정 폭에 가장 가까운 정수) · 불길 2 · 중력장 구체 1~5(중첩 수) · 화염 폭발 3~6 · 중력 착탄 3~5(판정 지름에 가장 가까운 정수) · 대붕괴 3~13(중첩마다 두 칸 — `MageSkillEffects.CollapseArtScale`, 사용자 2026-11-09) | **정수**(그림 테두리와 판정 경계는 몇 px 어긋날 수 있다) |
| 투사체·경험치 구슬 | 원 128×128 · 128 | 쏠 때 크기(`sizeMul` 등)·구슬 지름 0.28 | 0.1~0.4 (매끈한 원) |

**섞이는 이유**: 그림마다 화면 크기를 따로 정하는데(위 표 '누가 정하나'), 지금 임시 그림은 그 값을 **판정 크기(키·반경)와 같게** 맞춰 두었기 때문이다(예전엔 코드가 판정에 맞춰 늘렸다 —
2026-11-06 3.5-d부터 그림 크기는 그림 데이터, 판정은 `EntitySizeConfig`·`colliderRadius`로 **따로**). 그래서 그림을 바꿀 때 그림 쪽 값만 맞추면 도트 배율을 고를 수 있고, 판정은 그대로다.

## 3. UI (월드와 별도)

- UI는 월드 카메라가 아니라 **640×360 판**(`UI/Pixel/PixelCanvas`)에 그리고 화면에 맞춰 키운다(1080p 3배). UI 그림은 **PPU 100**, 판 1칸 = 그림 1픽셀.
- 그래서 같은 화면에서 **UI 한 칸 = 월드 1.5칸**이다(640 vs 960). 의도된 구성(Figma 640×360)이며 월드 규칙과 섞지 않는다.

## 4. 아직 정하지 못한 것 (외주 규격이 오면)

- 외주 VFX·캐릭터·배경·몹 그림의 **PPU와 실제 픽셀 크기**(예: 캐릭터를 몇 픽셀 높이로 그릴지).
- 효과 애니메이션의 **프레임 캔버스 크기·기준점(피벗)·프레임 수**.
- 배경 타일 경계·반복 규칙, 지역별 배경 구성.

## 5. 제안 (확정 아님)

- 월드 그림은 **도트 배율이 정수**(가능하면 1)가 되게 그리고 쓴다 — 예: 캐릭터 키 0.5유닛 = 64픽셀(PPU 128, 배율 1).
- 그림 크기와 판정 크기는 **분리돼 있다**(2026-11-06 3.5-d — 지금 화면 크기를 보존한 채). 최종 그림이 오면 그림 쪽 값(`heights`·`visualHeight`·`bossSize` 등)을 '도트 배율이 정수'가 되게 고른다 — 판정은 건드리지 않는다.
- **기준점(피벗)은 가운데**로 가져온다(배경·포탈·몹 — `StageVisuals.BackgroundPosition`·`BossPortal.ApplyArt`·스폰 높이가 가운데 피벗을 전제로 계산한다). 지금 그림은 전부 가운데(0.5, 0.5) — **예외: 캐릭터 그림(`char_*`)은 (0.5, 35/64)**(`Editor/BuildPrototypeSprites.CharacterPivotY`, Figma처럼 그림 바닥이 타일 윗면보다 3px 아래에 오게, 판정은 그대로). 외주 캐릭터 그림이 오면 이 값을 그 그림 기준으로 다시 정한다. 다른 피벗이 필요하면 그 계산도 같이 고친다.
- 도트 배율 보고서로 정수가 아닌 곳을 찾는다(지금은 경고만, 최종 그림이 오면 검사로 강화) — **메뉴 `ChronoSavior/도트 배율 보고서`**
  (배치: `-executeMethod ChronoSavior.Editor.DotScaleReport.RunBatch -reportOut <파일>`). 위 2절 표는 이 보고서와 같은 계산이다 — 그림을 바꾼 뒤엔 보고서를 다시 돌릴 것.
